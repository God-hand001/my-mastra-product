# M7 Word 文档生成引擎 Spec

> 产品:类千问办公的任务型 AI 助手(基于 Mastra harness)
> 编号:h0/m0-m3 已占用,m4「我的网页」m5「扩展体系」为路线图预留,M6 为内置浏览器,本次取 **M7**
> 背景调研:参考产品 WorkBuddy 桌面端的 `tencent-docx` 内置插件

## 背景

当前 agent 生成 .docx 的方式是**临时写一个 Node 脚本再执行**,带来四个实际问题(均由用户在使用中反馈):

1. **产物质量低**:脚本直接拼 OOXML 或用简单库,字体、字号、表格样式、页边距都靠模型逐个手写,中文字体尤其容易丢(Word 需要单独设置 `rFonts.eastAsia`,模型常漏)
2. **分页位置乱**:模型手动插分页符,结果是每章强制换页、页面没排满就跳页
3. **产生垃圾文件**:每次生成都留下 `gen_xxx.js`、`verify_xxx.js` 等一次性脚本,与最终文档混在一起
4. **不可复用**:每次重新写脚本,同类文档质量不稳定

调研参考产品后确认其做法是:**agent 写 HTML,再由 Python 转换器转成 .docx**(依赖 `python-docx` + `html-for-docx` + `beautifulsoup4` + `lxml`),并在产品内打包 Python 运行时。这个思路让模型只做它擅长的事(写结构化 HTML),字体与样式细节交给成熟库处理。

本模块采用同一思路,**自行实现转换器**(不复制参考产品代码),并把 Python 运行时随产品分发。

## 关键技术约束(先行说明,决定「不做的事」)

`python-docx` 与所有纯生成型库一样**没有排版引擎**,无法计算"这一页排满了没有"。因此本模块的分页仍然是**按语义分节**(HTML 的分节标记 → Word 分节符 → 预览器按节切页),而不是"内容排满自动换页"。真正的自动排版只有 Word / WPS / LibreOffice 这类完整排版引擎能做。

这一点必须在验收前达成共识:**本模块解决的是文档质量与分页可控性,不是像素级还原 Word 的自动排版**。

## 目标

- G1:agent 生成 Word 文档时不再写一次性脚本,改为写 HTML 并调用统一的转换能力
- G2:生成的文档具备可靠的中文字体、标题层级、段落样式与表格样式
- G3:分页位置由文档语义结构决定,可预期、可控制
- G4:端用户安装产品后即可使用该能力,无需自行安装 Python 或任何依赖
- G5:转换失败时 agent 能拿到可读的错误原因并自行修正 HTML 重试

## 功能需求

- **F1 HTML 转 Word 能力**:提供一个转换入口,接收 HTML 内容与输出路径,产出 .docx 文件;转换成功返回输出文件位置,失败返回结构化的错误原因(可区分:HTML 解析失败、样式不支持、写文件失败、运行时环境缺失)。
- **F2 中文字体正确**:生成文档中的中文字符使用指定中文字体且在 Word 中打开时不回退成默认字体;文档级默认字体与元素级字体覆盖均生效。
- **F3 结构与文本样式**:支持标题层级(至少三级)、段落、无序与有序列表、加粗斜体下划线、文字颜色、对齐方式、行距与段间距。
- **F4 表格样式**:支持表格边框、表头背景色、单元格内边距、列宽、单元格内的基本文本样式。
- **F5 语义分节控制分页**:HTML 中的分节标记转换为 Word 分节符,使预览器与 Word 都按此切页;同一节内的内容不被强制拆开。
- **F6 页面设置**:支持纸张尺寸与页边距设置,缺省为 A4 加常规页边距。
- **F7 Agent 调用规范**:agent 生成 Word 文档时,先产出 HTML 再调用转换能力;不再编写一次性生成脚本;转换失败时读取错误原因并修正 HTML 后重试(最多重试有限次数,失败则如实告知用户)。
- **F8 运行时随产品分发**:Python 运行时与全部第三方依赖随产品打包,端用户安装后开箱可用,不需要联网安装依赖、不需要系统已装 Python、不污染系统 Python 环境。
- **F9 环境自检与可诊断**:转换能力在运行时环境缺失或损坏时,返回明确指向具体缺失项的错误信息(而非泛化的失败),便于排查。
- **F10 自动目录**:HTML 中标记目录位置后,生成的文档在该处插入可跳转的目录域,收录三级标题;在 Word 中打开可通过"更新域"刷新页码。
- **F11 页眉页脚与页码**:支持设置页眉页脚内容,页脚支持"第 X 页 / 共 Y 页"形式的页码域;首页可单独设置(如封面无页眉页脚)。
- **F12 图片嵌入**:支持三种图片来源 —— 本地文件路径、base64 内联数据、远程 URL;支持设置显示宽度;图片获取失败时不中断整篇转换,该处以占位说明代替并在结果中报告。
- **F13 装饰组件**:支持四种排版组件 —— 标注框(带背景色与左侧色条的提示块)、分隔线、章节起始标记、数据卡片(含标题与数值的卡片,支持并排成组)。
- **F14 段前分页控制**:分页通过段落级"段前分页"属性实现,并正确处理两个边界 —— 表格无法承载该属性时改由前置锚点段落承载;目录等占位段落被移除时,其分页属性移交给紧随的下一段。

## 非功能需求

- **N1 离线可用**:首次使用与后续使用均不需要网络。
- **N2 隔离性**:打包的运行时与依赖不影响系统已安装的 Python(若有),也不被其影响。
- **N3 开发与生产一致**:开发环境(后端以 `npm run dev` 独立启动)与打包后的产品使用同一套运行时定位逻辑,不出现"开发能用、打包后找不到"。
- **N4 转换时长可接受**:常规长度文档(约 20 页以内)的转换在数秒内完成,不阻塞对话流。
- **N5 失败不留残件**:转换失败时不产生半成品 .docx 文件。
- **N6 不回退现有功能**:既有的 docx 预览(docx-preview 渲染)、产物标记与自动开签、脚本折叠展示等行为保持不变。

## 不做的事

- **排版引擎级自动分页**(按内容是否排满自动换页)。原因见「关键技术约束」;若后续确需,应另立模块评估引入完整排版引擎的代价。
- **复制参考产品的转换器实现**。只借鉴技术路线,依赖库用 PyPI 上的开源库,转换逻辑自行实现。
- 修订与批注、脚注尾注(参考产品的 docx 插件也未覆盖这两项)。
- 不做 .pptx / .xlsx 生成 —— 按用户要求这两项要做,但**另立里程碑**(见下方「里程碑划分」),不塞进本模块。原因是依赖集完全不同(pptx 用 python-pptx、xlsx 用 openpyxl + formulas),验收面各自独立,合成一个模块会让验收无法收敛。
- 不做已生成文档的二次编辑或增量修改(每次生成完整文档)。
- 不改动现有 docx 预览的渲染方式。

## 里程碑划分

办公文档生成按格式拆为三个独立里程碑,每个里程碑依赖集与验收面独立:

- **M7(本模块)Word 生成引擎**:HTML → .docx。依赖 python-docx、html-for-docx、beautifulsoup4、lxml、Pillow、httpx;同时落地「产品内打包 Python 运行时」基础设施(Windows embeddable 发行版 + 预装依赖 + 开发/生产一致的定位逻辑)。**这套运行时是后两个里程碑的公共前置。**
- **M8(预留)PPTX 生成**:依赖 python-pptx,复用 M7 运行时;需同步补 pptx 预览(当前预览栈 docx-preview / SheetJS / pdfjs 均已就位,唯独缺 pptx 渲染)。
- **M9(预留)XLSX 生成**:依赖 openpyxl + formulas(公式重算)。注意:参考产品的 Excel 路线是「agent 自己写 openpyxl 脚本」——这正是本模块在 Word 上要淘汰的模式,届时需先决策生成模式(固定转换器 vs agent 脚本)再动工。

顺序:M7 → M8 → M9。

## 验收标准

- **AC1**(F1):给定一段包含标题、段落、列表、表格的 HTML,调用转换能力后在指定路径产出 .docx,该文件能被 Word 或 WPS 正常打开且内容与 HTML 对应。
- **AC2**(F1、F9):给定一段明显非法的 HTML(如未闭合的畸形结构)或不可写的输出路径,转换返回可读的错误原因,且能从错误信息判断属于哪一类失败。
- **AC3**(F2):生成的文档在 Word 中打开时,中文段落显示为指定中文字体而非默认字体;检查文档内部结构可见中文字体设置已写入。
- **AC4**(F3):三级标题、有序/无序列表、加粗斜体、文字颜色、居中对齐在生成的文档中均正确呈现。
- **AC5**(F4):表格具有可见边框、表头有背景色、列宽符合设定。
- **AC6**(F5):含三个语义分节的 HTML 转换后,文档在 Word 与右侧预览面板中均显示为三页(或三节),节内内容未被拆散。
- **AC7**(F6):生成文档的纸张尺寸为 A4,页边距符合设定值。
- **AC8**(F7):让 agent 生成一份多章节 Word 文档,观察其行为:产出的是 HTML 加一次转换调用,工作区内**不再出现** `gen_xxx.js` / `verify_xxx.js` 一类临时脚本。
- **AC9**(F8、N1、N3):在未安装任何 Python 的机器上,后端以开发方式启动后该能力可直接使用;断网后仍可使用。
- **AC10**(N5):制造一次转换失败后,检查输出目录未残留半成品 .docx。
- **AC11**(N6):本模块上线后,既有的 docx 预览、产物卡片与脚本折叠、任务摘要、内置浏览器均按原样工作。
- **AC12**(F10):含目录标记与多级标题的 HTML 转换后,文档在 Word 中打开可见目录,收录到三级标题,点击条目可跳转到对应位置。
- **AC13**(F11):生成文档的页脚显示"第 X 页 / 共 Y 页"且翻页时页码递增;设置了封面时首页不显示页眉页脚。
- **AC14**(F12):三种来源(本地路径、base64、远程 URL)的图片均正确嵌入文档并按设定宽度显示;把其中一个来源改为不存在的地址后,转换仍然成功,该处显示占位说明,且结果中报告了该图失败。
- **AC15**(F13):四种装饰组件在生成文档中呈现为预期样式 —— 标注框有背景色与左侧色条、分隔线为横线、数据卡片显示标题与数值且并排成组时横向排列。
- **AC16**(F14):含表格的分节转换后不报错且表格前正确换页;含目录的文档在目录占位段落被移除后,其后第一段仍从新页开始。
