### 打开方式子菜单（本次修复重点，多轮迭代）
- [x] PowerShell 枚举脚本重写：直接读注册表（HKCR/HKCU FileExts），不再用 `Get-AppxPackage`/`Get-StartApps` 慢路径，枚举耗时从 14-25s 降到 1.1-1.7s（缓存命中 <0.5s）
- [x] 应用名改用 exe 的 `FileDescription`（"Microsoft Edge"/"WPS Office"），而非 ProgID 的 `FriendlyTypeName`（"Microsoft Edge HTML Document" 这类类型名）
- [x] 解决 PowerShell 5.1 的两个环境坑：无 BOM UTF-8 中文注释导致解析器崩溃（脚本改纯 ASCII 注释）；`ConvertTo-Json -InputObject <List>` 抛类型不匹配（改逐条序列化后手工拼数组字符串）
- [x] 前端子菜单改用 `createPortal` 渲染到 `document.body` + `fixed` 定位，解决：菜单被卡片边界裁剪、贴视口底部时只剩一项、子菜单与主菜单重叠
- [x] 修复"点击应用没反应"根因：原 `/open`、`/open-with` 端点用 `cmd.exe /c "start ... "..."""` 拼接字符串执行，Node 在 Windows 下对参数的引号转义规则与 cmd.exe 的解析规则不一致，命令常被打烂；且原 `execPromise` 的 `resolve()` 在 spawn 的 `error` 事件之前就同步调用，失败被完全吞掉，前端永远收到 `{ok:true}`。修复：新增 `spawnDetached`/`parseCommandLine`/`openWithCommand`，不经过 shell、直接把命令行解析成 `[exe, ...args]` 传给 `spawn`，并等待 `spawn`/`error` 事件才决议 Promise
- [x] 用真实文件验证：html 用默认程序（Edge）打开 ✓，html 用非默认程序（Chrome）打开 ✓，docx 用 WPS 打开 ✓ —— 均以 `tasklist` 确认进程真实启动且有实际内存占用
- [ ] **待用户在桌面端 UI 上确认**：以上修复验证均通过 curl 直连后端完成，尚未通过真实点击 UI 菜单项回归确认
