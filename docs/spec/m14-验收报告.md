## 交付物核对（发现并修复 1 处问题）

codex 完成后自报四改一新，`npx tsc --noEmit`、`cd app && npm run build` 均通过。逐文件核对时发现：

**问题：`app/src/components/TaskMonitor.tsx` 全文中文被写坏成 `?` 字符**（`file` 命令显示为纯 ASCII，而非 UTF-8）。根因与已知坑一致（见 memory `codex-dispatch-discipline`）：codex 用 PowerShell 管道拼接 heredoc 传给 `node -e "...writeFileSync..."` 写文件时丢了编码。因为 `?` 是合法 ASCII 字符，tsc 和 vite build 都不会报错，这类损坏**编译检查发现不了，必须逐文件核对内容**才能发现。

**修复：** 用 Write 工具以正确 UTF-8 重写了整个 `TaskMonitor.tsx`（逐处还原中文文案，逻辑保持 codex 原实现不变）。同时清理了 `TaskPage.tsx` 里遗留的两行调试残留代码（codex 排查类型错误时插入的 `const __rawMessages = ...` 死代码，缩进也不对）。

修复后重新跑通：
- 根目录 `npx tsc --noEmit` → 无输出（通过）
- `cd app && npx tsc --noEmit -p tsconfig.json` → 无输出（通过）
- `cd app && npm run build` → `✓ built in 14.42s`（仅有 codebase 既有的 zod 注释警告与 500KB chunk 警告，非本次改动引入）

其余三个改动文件（`PreviewPanel.tsx`、`TaskPage.tsx`、`workspace-routes.ts`、`app.css`）核对为正常 UTF-8(BOM)，中文文案完整，未发现问题。

## 遗留事项

1. **需要用户在真实浏览器里做一轮目测验收**：面板视觉布局、待办随对话实时滚动更新的观感、点击定位图标后 explorer 是否弹出、折叠展开交互、键盘导航（Tab→Enter 开菜单等，N6）——这些主 agent 没有浏览器自动化工具，无法代为验证
2. **长期记忆"有历史摘要"正例未验证**：建议用户找一个较长的真实任务线程手动点一次"压缩上下文"按钮，之后打开任务监控确认长期记忆区正确显示"有历史摘要"、短期记忆区正确显示"已压缩 N 次"徽标
3. **F16 的"空闲降频"未实现**：codex 按指令书里注明的从简处理,工作文件与短期记忆用量固定 3s 轮询,未做空闲时降到 15s 的精细状态机（功能上不影响正确性,只是空闲时轮询频率高于 spec 期望）
4. **工作文件的"任务起点"判定简化**：`workspaceSinceRef` 统一取组件 mount 时刻，未区分"新任务 vs 历史任务取首条用户消息时间"（spec plan 里提到的更精细方案），实际影响：刷新页面重新打开一个历史任务时，工作文件列表的时间窗口会从"刷新那一刻"重新计算，可能让本该显示的历史工作文件被漏掉。这是已知简化，如果用户认为影响体验可以后续单独排期
5. **本次改动引入的两处 codex 自身操作失误**（均已修复，记录留痕）：TaskMonitor.tsx 中文编码写坏（已用 Write 工具重写修复）、TaskPage.tsx 遗留调试死代码（已清理删除）
