# M12 执行过程可观测化 Spec

## 背景

当前对话界面把 Agent 的执行过程当作黑盒处理，用户提出任务后只能看到一行占位文字，直到最终答案出现。具体现状：

- **流式过程中**：消息区只渲染一行进度（转圈 + 一句阶段文字，如「正在思考…」「正在执行命令…」），中间步骤完全不可见。用户无法判断 Agent 在做第几步、是否卡住、是否走错方向。
- **一轮结束后**：所有中间步骤被压进一个默认收起的「任务已完成 ›」折叠块。展开后只有工具名 + 「已完成」，以及原始 JSON 形式的参数和结果。
- **输入框上方的进度条**：文案硬编码为「处理中...」，不随实际阶段变化。
- **文件写入类工具**：卡片只显示 JSON 参数，看不出这次改动到底改了哪几行。后端 `project_write_file` 也只返回 `{path, bytes}`，缺少构造差异所需的原始内容。
- **模型的中间叙述文字**（如"docx 包未预装，安装一下："）与最终答案混在同一层，被折叠逻辑一并收走或一并暴露，没有区分。

已有基础设施：消息转换层已能解析 `reasoning` 类型的消息片段并转成前端可渲染的形态；工具调用已有独立卡片组件与一套工具名到中文文案的映射规则；每条回复的耗时与 token 统计已在前端维护。

本期要做的是把这些零散能力组织成一套完整的执行过程呈现：过程在跑的时候可见、结束后可回看、状态文案如实反映当前阶段、文件改动显示真实差异。

## 目标

- 执行过程在流式进行中内联可见，用户能实时看到 Agent 想了什么、调了什么工具、结果如何
- 一轮结束后过程自动收起，最终答案保持突出，不被过程淹没
- 模型的推理、中间叙述、工具调用三类内容在视觉上分层，各自有合适的呈现形态
- 工具调用卡片显示结构化信息而非原始 JSON；文件写入显示真实的行级改动差异
- 输入框上方的运行状态文案如实反映当前阶段（思考中 / 调用工具 / 执行命令 / 等待授权等）

## 功能需求

### 过程呈现结构

- **F1 三层内容分层**：assistant 消息的中间过程按内容类型分三层呈现。模型推理内容进入独立的可折叠「深度思考」区块；模型的中间叙述文字以正文形态直接展示，不被折叠；工具调用以独立卡片展示。三者按产生的时间顺序交错排列，还原「说一句话 → 做一件事」的节奏。

- **F2 流式中过程内联展开**：一轮回复流式进行期间，上述三层内容随流实时出现在消息区内，无需用户操作即可见。已产出的内容保持可见，不因新内容出现而被替换或隐藏。

- **F3 结束后自动折叠**：一轮回复结束后，中间过程自动收起为一行摘要（可点击展开回看），最终答案正常展示在摘要行下方。纯对话（无任何中间步骤）不出现摘要行。

- **F4 折叠摘要行反映真实结束状态**：摘要行文案区分正常完成与非正常结束。工具因等待用户授权而挂起时，摘要行显示等待授权而非任务已完成。

- **F5 历史消息可回看过程**：刷新页面或重新进入任务后，历史回复的中间过程仍可通过展开摘要行查看，呈现形态与实时产生时一致。

### 深度思考区块

- **F6 思考区块可折叠**：模型推理内容收纳在默认折叠的区块中，标题标明这是思考内容。用户点击展开可读完整推理。

- **F7 思考内容流式追加**：推理内容在流式产生过程中逐步追加显示，用户能感知推理正在进行。流式期间该区块默认展开，一轮结束后随整体过程一并收起。

- **F8 思考耗时**：思考区块标题显示本段推理消耗的时长。流式中显示进行时状态，结束后显示最终耗时。

- **F9 模型无推理输出时不显示空区块**：当前模型不产出推理内容时，不出现空的思考区块，过程呈现降级为「叙述文字 + 工具卡片」两层，其余功能不受影响。

### 工具调用卡片

- **F10 结构化卡片**：每次工具调用呈现为一张卡片，包含该工具的中文动作描述、当前状态、以及可展开的参数与结果详情。卡片标题使用中文动作文案（如「已读取项目文件」）而非原始工具标识。

- **F11 状态可视化**：卡片状态区分进行中（含动态指示）、已完成、失败三种，视觉上可直接区分。状态随工具生命周期实时更新，无需刷新。

- **F12 关键参数摘要**：卡片在未展开时显示该次调用最关键的一个参数摘要（如文件路径、命令内容、搜索关键词），用户不展开也能知道这一步操作的对象。参数摘要过长时截断。

- **F13 文件写入显示真实差异**：文件写入类工具的卡片展示行级改动差异：新增行、删除行分别标记，并显示增删行数统计。新建文件时全部内容按新增呈现。差异内容过长时截断并标明。

- **F14 结果按类型呈现**：工具结果按内容类型选择呈现方式，纯文本结果按文本展示，结构化结果按可读的层级展示，不直接倾倒原始序列化文本。结果过长时截断并标明。

- **F15 失败原因可见**：工具执行失败时，卡片在未展开状态下即显示失败原因摘要，展开可见完整错误信息。

### 运行状态文案

- **F16 状态文案反映当前阶段**：输入框上方的运行状态行，文案随 Agent 当前实际阶段变化，至少区分以下阶段：正在思考、正在调用工具（含具体工具的中文动作）、正在执行命令、正在生成回复、等待用户授权。

- **F17 状态文案与工具文案统一**：状态行中涉及具体工具的文案，与工具卡片标题使用同一套工具名到中文的映射规则，同一个工具在两处的说法一致。

- **F18 未知工具有兜底文案**：遇到映射规则未覆盖的工具（如连接器动态接入的工具），状态行与卡片标题均显示可读的兜底文案，不显示原始标识或空白。

### 后端支持

- **F19 文件写入返回差异数据**：文件写入类工具在返回结果中附带构造行级差异所需的数据（写入前的原内容或已算好的差异），供前端渲染 F13。文件不存在时明确标识为新建。

- **F20 差异数据体积受控**：差异数据超过约定上限时，后端截断并在结果中标明被截断，避免大文件写入把消息体撑爆。

## 非功能需求

- **N1 向后兼容历史消息**：改动不破坏已存储的历史消息渲染。历史消息缺少新增字段（如差异数据）时，卡片降级显示已有信息，不报错、不空白。

- **N2 长任务下的性能**：Agent 单轮最多可执行 100 步。过程内联展开时，界面在数十次工具调用的情况下仍可正常滚动与交互，不出现明显卡顿。

- **N3 不改变现有交互契约**：不影响现有的重新生成、复制、停止、沙箱审批弹窗、耗时与 token 统计等已有功能的行为。

- **N4 中文界面**：所有面向用户的文案为中文，与现有界面文案风格一致。

- **N5 视觉一致性**：新增与改造的界面元素沿用项目现有的配色、圆角、字号、间距规范，不引入新的视觉语言。

- **N6 无障碍**：折叠区块可用键盘操作并有正确的展开状态语义；状态变化对屏幕阅读器可感知；颜色不作为区分状态的唯一手段。

- **N7 安全**：差异数据与工具参数在界面呈现前做转义，不因文件内容包含标记语言而导致注入。后端返回的原文件内容仅用于呈现，不放宽既有的项目目录访问边界。

## 不做的事

- **独立的执行轨迹面板**：每步 token 消耗、上下文占用分布图、加载文件清单等汇总视图不在本期范围。这类面板需要从后端观测数据取数并新开接口，与对话流内的可观测性是两件事，留待后续里程碑。
- **沙箱命令写入的文件差异**：Agent 通过沙箱执行命令间接写入的文件，前端无法获得写入前后内容，本期不为这类改动构造差异。仅文件写入类工具支持 F13。
- **过程内容的搜索与过滤**：不提供在过程步骤中搜索、按类型过滤、跳转到某一步的能力。
- **过程呈现的用户偏好设置**：不提供「默认展开/折叠」「隐藏思考内容」等开关，行为按本 spec 固定。
- **切换模型以获得推理内容**：不为了让思考区块有内容而调整默认模型或模型参数。F9 已约定模型不产出推理时的降级行为。
- **工具卡片的重试与编辑**：卡片是只读呈现，不提供重跑某一步、修改参数重试等操作。
- **多轮回复的过程聚合**：不跨消息聚合过程步骤，每条 assistant 消息的过程独立呈现。

## 验收标准

- **AC1**（对应 F1、F2）：向 Agent 提一个会触发多次工具调用的任务，流式进行期间在消息区可依次看到推理区块、模型叙述文字、工具卡片三类元素，按时间顺序交错排列，已出现的内容不消失。
- **AC2**（对应 F3）：上述任务结束后，中间过程收起为一行摘要，最终答案在摘要行下方完整可见；点击摘要行可重新展开看到全部过程。
- **AC3**（对应 F3）：向 Agent 发一句不需要任何工具的闲聊，回复中不出现过程摘要行。
- **AC4**（对应 F4）：触发一个需要沙箱授权的操作，在授权弹窗出现时观察摘要行，文案为等待授权而非任务已完成。
- **AC5**（对应 F5）：完成一个多步任务后刷新页面，展开该条回复的摘要行，过程内容与刷新前一致。
- **AC6**（对应 F6、F7、F8）：模型产出推理内容时，思考区块在流式期间展开并逐步追加文字，标题显示进行时状态与耗时；一轮结束后区块随过程收起，标题显示最终耗时。
- **AC7**（对应 F9）：使用不产出推理内容的模型完成一个多步任务，界面不出现空的思考区块，叙述文字与工具卡片正常呈现。
- **AC8**（对应 F10、F12）：观察任一工具卡片，未展开状态下即可看到中文动作描述与关键参数摘要（如具体文件路径），无需展开就能判断这一步在操作什么。
- **AC9**（对应 F11）：工具执行期间卡片显示进行中状态与动态指示，执行完成后自动变为已完成状态，无需刷新页面。
- **AC10**（对应 F13、F19）：让 Agent 修改一个已存在的项目文件，卡片显示新增行与删除行的行级差异及增删行数；让 Agent 新建一个文件，卡片显示全部内容为新增。
- **AC11**（对应 F14）：展开一个返回结构化结果的工具卡片，结果以可读的层级形式呈现，不是单行原始序列化文本。
- **AC12**（对应 F15）：让一个工具执行失败（如读取不存在的文件），卡片未展开即显示失败原因摘要，展开可见完整错误。
- **AC13**（对应 F16）：在一次多步任务执行过程中观察输入框上方的状态行，文案随阶段变化，能观察到思考、调用工具、执行命令等不同文案，而非固定一句。
- **AC14**（对应 F17）：某个工具执行期间，对比状态行文案与该工具卡片标题，两处对同一工具的中文说法一致。
- **AC15**（对应 F18）：调用一个连接器提供的工具，状态行与卡片标题显示可读的兜底中文文案，不出现原始工具标识或空白。
- **AC16**（对应 F20）：让 Agent 写入一个较大的文件，卡片差异区显示被截断的标明，界面不卡顿。
- **AC17**（对应 N1）：查看本次改动前已存在的历史消息，工具卡片正常显示已有信息，不报错、不空白。
- **AC18**（对应 N2）：执行一个触发数十次工具调用的任务，过程展开状态下滚动对话区，滚动流畅无明显卡顿。
- **AC19**（对应 N3）：对一条已完成的多步回复点击重新生成，新回复的过程呈现正常，耗时统计重新计时；沙箱审批弹窗、复制、停止功能行为不变。
- **AC20**（对应 N6）：用键盘 Tab 与回车操作思考区块与工具卡片的折叠，可正常展开收起；不依赖颜色也能区分工具的三种状态。
