# M15 场景工作台角色切换 Spec

## 背景

学习项目需要研究 Agent 前端交互与角色编排。当前产品所有对话共用一个 Agent 配置（同一 system prompt、同一技能集），用户希望按场景切换角色（通用/设计师/幻灯片/写作），每个角色是一套完整配置包：专属 System Prompt + 技能集 + 产物格式约束 + 前端默认渲染器。

逆向分析（m15-逆向分析.md）确认千问的双通道架构：① 切换即持久化到会话字段（刷新/换会话可恢复）；② 每条消息提交体显式携带角色（单条消息角色必然正确）。本项目对齐此架构：前端 Zustand per-thread 持久化 + 每请求 requestContext 携带 role；后端 agent 按角色动态组装 instructions 与技能过滤（复用 M10 技能 resolver）。

## 目标

- 输入框连接器按钮的右边新增角色选择器，4 个内置角色；**新任务时选定角色，发出首条消息后角色锁定**（对齐千问实机行为，2026-09-18 用户修正）
- 每个会话的角色随会话持久化：重新进入历史会话自动恢复该会话角色并按角色渲染右侧工作区；锁定会话不再提供切换入口
- 角色约束模型把交付产物放进 `<artifact>` 标签；前端剥离标签送右侧预览面板，按角色选择渲染器
- 代码可扩展（后续新增角色只需加配置）

## 功能需求

### 角色定义

- **F1 角色配置结构**：每角色包含 id、label、icon、systemPrompt（追加在基础指令之后的专属指令）、enabledSkills（该角色允许的技能名单）、artifactType（产物类型：none/html/slides/doc）、defaultRenderer（前端渲染器标识）、artifactHint（指导模型输出格式的短句，拼入 systemPrompt）
- **F2 四个内置角色**：
  - `general` 通用：不追加专属指令，artifactType=none，不强制产物，Markdown 渲染
  - `design` 设计师：网页 UI 设计，强制生成单文件 HTML 产物置于 `<artifact type="html">`，技能含前端设计相关
  - `slides` 幻灯片：先输出大纲征求确认，确认后生成幻灯片 HTML 产物（`<artifact type="slides">`，每页一个 section 结构，含 PPTX 导出路径——复用 M7 html-to-pptx 转换约定）
  - `writing` 写作：长文档 Markdown 报告/方案，产物 `<artifact type="doc">` 内为 Markdown 源，支持导出 Word（复用 M7 html-to-docx 链路，Markdown→HTML→docx）
- **F3 角色扩展性**：新增角色仅需在配置常量数组追加条目，不改选择器/请求层/渲染层代码

### 状态与切换

- **F4 Zustand 会话状态**：`useRoleStore` 维护 `Map<threadId, RoleId>` 与当前激活 threadId 的派生选择器；localStorage 持久化（key `workbench:sessionRoles`），应用启动恢复
- **F5 角色锁定**（对齐千问实机，2026-09-18 用户修正）：切换器**仅在新任务（thread 无任何消息）时显示**；发出首条消息后角色即锁定，切换器从工具栏消失，该会话后续所有请求沿用锁定角色；已锁定角色的会话不可更换角色
- **F6 会话恢复**：切换 thread 时按 store 恢复该 thread 的角色并驱动对应右侧工作区；已锁定的历史会话**不显示**切换器（与千问一致：design/writing 会话工具栏无切换入口）；新 thread 默认 general 并显示选择器

### 请求链路

- **F7 请求携带**：transport 的 requestContext 增加 `role: RoleId`（复用现有 requestContext 机制，与 model/skill 同通道）
- **F8 后端组装**：agent.ts instructions 拼接：基础指令 + 当前角色的 systemPrompt + artifactHint；skills resolver 过滤：角色 enabledSkills 非空时仅暴露交集，general 时不限制
- **F9 技能指定兼容**：现有斜杠技能指定（requestContext.skill）与角色共存：显式指定的技能优先（可突破角色白名单）

### 产物识别与渲染

- **F10 标签协议**：模型输出 `<artifact type="html|slides|doc" title="...">内容</artifact>`；前端解析、从聊天流剥离为产物卡，内容送右侧预览面板
- **F11 渲染器路由**：右侧面板按 artifact type 渲染——html → 沙箱 iframe（`sandbox="allow-scripts allow-forms"`，**禁止 allow-same-origin**），生成前显示骨架占位（对齐千问「正在生成画布…」设计）；doc → Markdown 渲染 + 导出 Word 按钮；slides → 右侧切换为幻灯片工作区，含三个标签：幻灯片（iframe 渲染产物 HTML，1280×720 画布适配缩放）、大纲（展示该产物会话中模型输出的大纲文本，取最新一条）、源文件（产物 HTML 源码查看，可复制）；general 无标签产物走现有【产物:】机制不变。千问同款认知：幻灯片产物 HTML 自带工作台 UI（缩略图/翻页/演讲稿），原生面板只提供标签壳与画布缩放
- **F12 角色辅助识别**：剥离时若标签缺 type，取当前会话角色的 artifactType 补齐
- **F13 兜底**：模型未按要求输出标签 → 内容按普通 Markdown 渲染，不报错；slides 角色下未生成产物前的大纲输出正常展示

### UI

- **F14 RoleSelector**（对齐千问实机）：常驻**连接器按钮右侧**（工具栏左组），触发按钮 = `图标 + 当前角色名 + ▾` 胶囊；展开纵向菜单，每项 = 图标 + 名称，当前角色绿色对勾（**无描述文字**，与千问一致）；点击即切换，菜单关闭；点击菜单外部关闭。**仅新任务（thread 无消息）时显示**——首条消息发出后按钮消失（F5 角色锁定）
- **F15 切换反馈**：切换后输入框 placeholder 或提示条短暂显示「已切换到{角色名}」，不阻塞输入

### 结构化提问（Ask User Question）

- **F16 提问工具**：design/slides 角色解锁 `ask_user` 工具——模型需要澄清需求时调用，携带问题数组（每项：编号、标题、说明、类型 single/multi/text、选项列表（标题+说明）、是否允许自由填写）。调用后会话挂起等待用户回答（复用 M11 沙箱审批的 suspend/恢复机制；agent.ts 中此前因缺 UI 配合而移除的 ask_user 由此恢复）
- **F17 问题面板**：右侧预览面板动态新增「问题」标签并自动激活（仅存在活跃问题时出现）；渲染问题表单：编号+标题+说明+选项卡（单选圈/多选框，选项含标题与说明）+「其他（请填写）」文本输入；底部「提交答案」与「AI 自行决定」两个动作
- **F18 提交与恢复**：提交答案 → 以工具结果回传模型恢复执行，模型按答案继续；「AI 自行决定」→ 以空答案恢复（模型自行决策）；挂起期间输入框上方状态行显示「等待你的回答…」并持续计时；恢复后「问题」标签保留最近一次问答记录

## 非功能需求

- **N1 Zustand 引入**：新增 zustand 依赖（学习目的：掌握主流会话状态管理）；其余模块不迁移
- **N2 安全**：HTML/slides 产物 iframe 沙箱禁止 allow-same-origin；产物内容纯文本/受控渲染；角色 systemPrompt 为代码内置常量不来自用户输入
- **N3 兼容**：不改变现有【产物:】标记、技能指定、模型选择的任何行为；未选角色（general）时请求体与现状等价
- **N4 中文**：角色名/描述/提示中文
- **N5 学习注释**：核心文件（store/类型/请求适配/标签解析）带教学级中文注释，解释"为什么这么设计"（双通道持久化、角色-技能过滤时机、剥离渲染分离）

## 不做的事

- legokit 式可安装角色包（市场化）——只做内置 4 角色常量
- writing 模式的「.md 文件树」形态（千问实机为：Agent 创建 .md 文件后右侧自动显示文件树）——本项目保持产物卡形态（消息流剥离 + 单产物渲染），文件树思路已由 M14 任务监控的工作文件区覆盖；后续需要可合并
- 服务端会话角色字段——用前端持久化 + 请求内联替代（千问双通道简化为「前端持久化 + 请求内联」；服务端字段留待多端同步需求出现再加）
- 幻灯片模板选择器（chatInputContexts 动态选项）——slides 角色大纲确认流已覆盖核心工作流
- 角色专属欢迎页示例
- 写作/幻灯片产物的在线协同编辑

## 验收标准

- **AC1**：新任务（空会话）输入框工具栏出现角色选择器，4 角色可切换，当前角色有勾选标识
- **AC2**：设计师角色要求生成网页 → 模型输出 `<artifact type="html">`，对话流中无大段代码，右侧面板 iframe 渲染页面，可源码/预览切换
- **AC3**：设计师产物 iframe 的 sandbox 属性为 `allow-scripts allow-forms` 且无 allow-same-origin（DevTools 验证）
- **AC4**：幻灯片角色 → 先收到大纲文本，回复确认后收到 slides 产物，右侧渲染；导出 PPTX 可得文件
- **AC5**：写作角色 → 产出 doc 产物，右侧 Markdown 渲染，导出 Word 成功打开
- **AC6**：发出首条消息后选择器消失（角色锁定），该会话内不再出现切换入口；历史消息与新回复均不受影响
- **AC7**：切换 thread → 已锁定会话不显示选择器且右侧工作区按该会话角色渲染；重启应用仍恢复（localStorage）
- **AC8**：通用角色请求行为与现状等价（无额外约束、无标签强制）
- **AC9**：模型未输出标签时（要求它"直接文字回答"）→ 正常 Markdown 展示无报错
- **AC10**：`<artifact>` 缺 type 属性时按当前角色 artifactType 正确路由渲染
- **AC11**：新增第 5 个角色（测试用假角色）只需改配置数组即可出现在选择器并生效（代码走查 + 临时实验）
- **AC12**：安全走查：产物 iframe 无 allow-same-origin；角色 systemPrompt 无用户可控注入面
- **AC13**（F16-F18）：设计师角色说「做一个房屋设计」→ 右侧出现「问题」标签并渲染结构化表单（编号/标题/单选选项/其他填写），状态行显示等待回答；提交答案后模型按答案继续；「AI 自行决定」可跳过；general 角色不出现 ask_user 工具
- **AC14**（F16）：挂起期间再发消息不产生新回复流（会话处于等待回答状态），提交后统一恢复——无双重执行
