# M11 沙箱体系(子进程内核级围栏) Spec

> 产品:类千问办公的任务型 AI 助手(嘉立创办公,基于 Mastra harness)
> 编号:本次取 **M11**;m10-spec.md 原将 M11 预留给「伙伴(专家/子代理)」,该模块顺延至 **M12**
> 技术来源:codex 的 Windows 沙箱(E:\code_agent\codex,Apache 2.0),以子进程 CLI 方式调用,不复制代码
> 前置:Phase 0(可行性验证)与 Phase 1(统一沙箱运行时模块)已完工,本 spec 覆盖 Phase 2 与 Phase 3

## 背景

产品的文件工具有真实围栏(工作区文件系统按 realpath 做包含性检查,可拦符号链接逃逸),但**子进程完全裸奔**:

- **命令执行**:无任何限制,可用任意绝对路径作为工作目录,shell 元字符全部生效
- **表格建表**:执行 agent 现场编写的 Python 脚本,防线只有 5 条正则黑名单(`pip install`/`subprocess`/`os.system`/`eval(`/`exec(`),拦不住 `open()` 直写、`__import__`、`importlib`、`shutil`、`socket`
- **连接器**:按配置拉起无约束子进程,配置里的目录占位符只是约定,无强制力

结果是 agent 写的脚本以当前用户的全部权限运行:能读 `.env`、SSH 私钥、浏览器 cookie,并联网外发。文件工具那层围栏,一条命令即可绕过。

**已完工的前置(不在本 spec 的需求范围内,仅作现状)**:
- 可行性验证全绿:裸跑沙箱 6/6、Mastra 接线 7/7、完整隔离档 7/7(两套凭据目录各一次)
- 统一沙箱运行时模块建成,冒烟测试 15/15 真实执行通过
- 关键实测结论:越界写被内核拒绝(而非字符串匹配);敏感读在完整隔离档可拦;网络可断;沙箱身份产出的文件后端可读可删(预览链路无需改动);稳态开销 1.3–2.0s

**但该模块尚未被任何地方调用**,产品当前行为与接入前完全一致。本 spec 要完成的是接管与逃生通道。

**两档能力边界是硬约束**(源于受限令牌的语义,非配置问题):免管理员档只能强制「写」限制;拒绝读取、网络阻断需要完整隔离档,后者要一次性管理员初始化(建专用本地账户,已在本机完成)。

## 目标

- **G1**:四处子进程调用点(表格建表、命令执行、两个文档转换器、连接器)全部经沙箱执行,越界写与敏感读在内核层被拒
- **G2**:策略收敛为单一真源,取代现有四套各自为政的规则
- **G3**:沙箱拒绝后有逃生通道,对标 codex 的审批模型(事后启发式判定 → 前置闸门 → 审批请求带可读原因 → 用户决定 → 更宽策略重跑),默认 fail-closed
- **G4**:M7/M8/M9 三条已验收的文档生成流水线行为不变,断言脚本仍全绿
- **G5**:沙箱不可用时明确报错,而非静默降级为无防护执行

## 功能需求

### Phase 2 — 子进程接管

- **F1 表格建表脚本进沙箱**:agent 编写的建表脚本经沙箱执行。脚本在工作区内读写正常、产物正常落盘;越界写入被内核拒绝并返回可读原因。沙箱生效后**移除正则黑名单式的脚本内容检查** —— 它只查 5 个字符串,拦不住直接文件写入与动态导入,属于给人虚假安全感的防线。
- **F2 命令执行进沙箱**:命令执行工具的所有命令经沙箱执行,含 shell 操作符(重定向、逻辑与)、中文路径、含空格路径。**前台执行与后台进程两条路径都必须覆盖** —— 只覆盖一条会留下静默漏洞。
- **F3 文档转换器进沙箱**:Word 与 PPT 转换器经沙箱执行。两者当前把任务文件落在用户临时目录,沙箱身份写不进去,因此**临时工作文件改落可写根内**。转换的输入输出契约(HTML 进、文档出)不变。
- **F4 连接器进沙箱**:连接器的服务器子进程经沙箱启动。**网络按连接器单独配置** —— 默认断网,但以联网为职责的连接器(如网页抓取类)需显式放行,否则其功能直接失效。启动失败原因仍显示在扩展面板,单个连接器失败不影响其他。
- **F5 策略单一真源**:读、写、网络三轴的策略由统一模块产出,提供三档预设(只读、工作区可写、项目目录可写)。各工具按需选档,不再各自实现规则。现有的路径校验作为纵深防御**全部保留**,不因有沙箱而删除。

### Phase 3 — 逃生通道(对标 codex)

- **F6 拒绝可判定与可读**:子进程失败时区分「疑似被沙箱拒绝」与「命令自身失败」,前者生成人类可读的原因(含被拒的路径或主机名)回给 agent。判定为启发式 —— codex 自身亦承认无法确定性区分,因此**不得用它做自动提权决策**,只用于生成提示。同时需防止 agent 对同一被拒操作反复重试。
- **F7 审批档位接线**:现有权限选择器的两档接到后端真实生效 —— 默认档在遇到拒绝时请求用户批准,完全访问档自动批准。档位随消息传递,切换后立即生效,无需重启。
- **F8 审批请求与决定**:沙箱拒绝且通过前置判定后,向用户呈现审批请求,内容包含将要执行的命令、工作目录、被拒原因、请求的额外权限范围。用户可选:本次允许 / 本会话内同类允许 / 拒绝但会话继续 / 拒绝并停止。**默认与超时均为拒绝**(fail-closed)。
- **F9 批准后重跑**:用户批准后以更宽策略重新执行同一命令。这是**新起一个进程**,不是给已退出的进程追加权限。重跑结果正常回流对话,agent 视其为该次工具调用的结果。
- **F10 启动自检**:服务启动时报告沙箱状态(档位、凭据目录、拒读路径条数)。沙箱不可用时给出明确错误与修复命令。

## 非功能需求

- **N1 性能开销可接受**:稳态单次沙箱调用开销 ≤2s。冷启动首次可达 16.5s,需在启动自检时预热,避免用户的第一次请求承担该延迟。拒读路径集合必须**逐次稳定** —— 集合一变即触发访问控制项重写,实测代价数秒。长驻型子进程只在启动时付一次开销。
- **N2 不回退既有功能**:M7/M8/M9 三条流水线的断言脚本保持全绿(基线 27/27、28/28、24/24;改动前需先复跑确认基线本身成立)。预览面板与产物标记链路正常。桌面壳、前端、技能与连接器体系不受影响。
- **N3 失败即拒,不静默降级**:沙箱二进制缺失、未完成初始化、或策略无法执行时,一律报错并中止该次操作,不退回无防护执行。
- **N4 机密不经环境变量外泄**:传入沙箱的环境变量最小化,不含模型 API 密钥等机密 —— 拒绝读取挡住了文件却让机密从环境变量漏给受限进程,等于白做。
- **N5 离线可用**:沙箱执行不需要网络(沙箱模式不调用模型、不需要密钥);一次性初始化亦为纯本地操作。
- **N6 错误可诊断**:沙箱相关错误必须写明尝试过的路径与具体修复命令,沿用项目既有的运行时定位错误约定。
- **N7 版本锁定**:策略参数是上游内部格式,无稳定性承诺。运行时版本锁定在安装脚本内;升级版本必须重跑验证脚本确认策略仍被接受。
- **N8 随产品分发**:沙箱运行时打包进产品(约 302 MB,版本控制排除、脚本可重建),**必须保留其原目录结构** —— 启动器按相对自身位置查找辅助程序,拍平会让完整隔离档失效。第三方二进制随包保留其许可声明。
- **N9 平台边界**:本期仅 Windows。其他平台各有独立的隔离后端,不在本期范围;非 Windows 平台需给出明确的不支持提示而非静默失败。

### 已知风险(需在设计阶段以实测消解)

- **R1 长驻双向 stdio 未验证**:连接器是长驻的双向会话,经沙箱启动会在链路上多一层转发进程。已验证的是短命令的 stdio 转发(拿到输出与退出码),**未验证长驻双向往返** —— 请求/响应能否正常来回、连接器存活期间流是否中断。若不成立,F4 需改方案(例如连接器单独走一档更宽策略,或暂缓接管)。
- **R2 挂起与恢复机制未验证**:F8/F9 需要「工具挂起 → 等用户决定 → 继续」的能力。框架侧已有工具审批标记与「自动恢复挂起工具」配置,但**二者在缺少前端审批界面时的真实行为尚未验证** —— 产品内的用户提问工具正是因缺该界面会永久挂起而被停用。设计阶段必须先以实测钉死此行为,再决定 F8/F9 走框架原生挂起还是自建链路。

## 不做的事

- **其他平台的隔离后端** —— 各是一套独立实现,本期只做 Windows
- **运行时瘦身** —— 现带整个上游 CLI(302 MB)只为用其中一个启动器分支;可自编约 10–15 MB 的等效瘦封装,但属发版前的打包优化,不阻塞功能
- **执行前预检** —— 不做静态分析预判命令是否越界;「命令会访问什么」在执行前不可知,codex 亦是事后判定
- **跨会话持久规则** —— 上游支持把批准写成永久策略修正,本期只做本次允许与本会话允许
- **细粒度审批开关** —— 上游按类别(命令/规则/技能脚本/权限请求/连接器询问)分别控制,本期用现有两档
- **主机级网络控制** —— 上游可按域名批准,本期网络只有断/通二值
- **私有桌面** —— 上游支持独立桌面以防窗口消息攻击,本期不启用
- **初始化向导** —— 一次性初始化仍走命令行;产品化的首次运行引导留待后续,本期只保证错误信息里给出可直接复制的修复命令
- **不删除现有防线** —— 既有的 realpath 围栏与路径校验全部保留;沙箱是加一层,不是换一层

## 验收标准

> **纪律**:每条「应被拒」必须配一条**同形式**的「应成功」。两者都失败说明命令根本没执行,拒绝断言无效 —— 该坑在 Phase 0 交过两轮学费(命令语法错误伪装成权限拒绝,导致假阳性通过)。

- **AC1**(F1):让 agent 生成含公式的表格 —— 产物落盘、公式重算通过;同形式让脚本写工作区外 —— 被拒且返回可读原因
- **AC2**(F1):表格建表工具中不再保留正则黑名单式的脚本内容检查
- **AC3**(F2):命令执行在工作区内创建目录与写文件成功(含中文名、含空格路径、含重定向与逻辑与的命令串);工作区外同形式操作被拒
- **AC4**(F2):后台进程路径同样经沙箱,不只前台执行路径
- **AC5**(F3):Word 与 PPT 端到端生成成功、产物可在预览面板打开;临时工作文件不落在用户临时目录
- **AC6**(F4):长驻连接器经沙箱启动后其工具可真实调用且多次往返不中断;默认断网连接器的网络访问受限,显式放行的连接器可联网
- **AC7**(F5):三档预设的读/写/网络边界符合定义,各工具所选档位可查
- **AC8**(F6):被沙箱拒绝的调用带「疑似沙箱拒绝」标记与可读原因;命令自身失败(如不存在的命令)不被误标
- **AC9**(F6):对同一被拒操作,agent 不会无限重试 —— 连续拒绝达到上限后转为如实告知用户,对话不陷入死循环
- **AC10**(F7):切到完全访问档后原先被拒的操作自动获批执行;切回默认档恢复审批行为
- **AC11**(F8):沙箱拒绝时用户看到审批请求,含命令、工作目录、被拒原因;选「拒绝但继续」时 agent 改换方案;无响应或超时按拒绝处理
- **AC12**(F9):批准后同一命令以更宽策略重跑成功,结果回流对话并被 agent 视为该次工具调用的结果
- **AC13**(F10):启动日志显示沙箱档位与拒读路径条数;把沙箱二进制改名后启动报明确错误并给出修复命令
- **AC14**(N2):三个断言脚本全绿;M7/M8/M9 各跑一次真实对话端到端交付成功;预览面板可打开沙箱身份产出的文件
- **AC15**(N1):稳态调用开销 ≤2s(连续多次测量取后续均值);启动预热后用户第一次请求不承担冷启动延迟
- **AC16**(N3):未完成初始化的环境下,工具调用返回明确错误而非无防护执行
- **AC17**(N4):传入沙箱的环境变量不含模型 API 密钥等机密
