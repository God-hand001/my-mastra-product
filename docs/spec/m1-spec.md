# M1 联网搜索 Spec

> 产品:类千问办公的任务型 AI 助手(基于 Mastra harness)
> 前置:M0 任务基座已验收通过([m0-spec.md](./m0-spec.md) 验收报告见会话记录)
> 里程碑路线:M0 ✅ → **M1 联网搜索** → M2 个人网盘+文档问答 → M3 定时任务 → M4 我的网页 → M5 扩展体系

## 背景

- M0 任务基座已验收:任务式界面、工具调用过程可见、任务内对话、历史持久化、Markdown 渲染
- 现状缺口:agent 只有 `web_fetch`(抓取已知 URL),**不能主动搜索**;回答时事类、知识盲区类问题时只能依赖模型旧知识,容易过时或编造
- M1 接入 **Tavily 搜索 API**(专为 AI agent 设计,免费 1000 次/月),agent 在任务中自主决定何时搜索;回答以 `[1]` `[2]` 内嵌标注 + 末尾来源列表呈现,对齐千问办公"AI 搜索"的体验
- 前置条件:已注册 Tavily 并将 key 存入 `.env`(`TAVILY_API_KEY`,已验证可用)

## 目标

- G1:agent 具备联网搜索能力,任务中自主调用(不需要用户指定"去搜")
- G2:搜索过程对用户可见(复用 M0 工具卡片:搜索词、状态、结果概要)
- G3:回答正文带 `[1]` `[2]` 内嵌标注,末尾附"来源"列表(标题 + URL)
- G4:搜索供应商隔离在工具实现层,后续可替换(博查等)而不动 agent 与界面

## 功能需求

- **F1 搜索能力**:agent 在任务中可自主发起联网搜索(无需用户指示"去搜"),搜索词由 agent 根据任务需要生成,中英文皆可
- **F2 搜索过程可见**:搜索调用复用 M0 工具卡片展示 —— 搜索词、运行状态、结果概要(搜到几条、来自哪些站点)
- **F3 内嵌标注**:回答中引用了搜索结果的内容时,正文以 `[1]` `[2]` 编号标注,编号全局连续
- **F4 来源列表**:回答末尾附"来源"小节:编号 + 来源标题 + URL,与正文标注一一对应;未使用搜索的回答不带来源小节
- **F5 供应商隔离**:搜索封装为独立工具模块,Tavily 的接口细节不泄漏到 agent 配置与前端界面;未来更换供应商(如博查)只改工具实现层

## 非功能需求

- **N1 健壮性**:搜索调用有超时上限(约 15 秒);搜索失败(网络/配额)不阻塞任务 —— agent 收到失败信息后可换词重试或继续回答
- **N2 安全**:Tavily key 只存 `.env`(git 忽略);agent 不把本地文件内容/密钥拼进搜索词(写入 instructions 约束)
- **N3 成本**:用量控制在 Tavily 免费额度内(1000 次/月),M1 不做缓存与配额面板
- **N4 架构边界**:前端零改动(来源列表是回答文本的一部分,由 agent 输出);改动集中在后端工具层

## 不做的事(M1)

- 搜索模式开关/"强制搜索"按钮等 UI
- 搜索结果缓存、月度用量统计
- 富引用卡片(站点图标、来源卡片组件)—— 留给打磨期
- Tavily 高级参数调优(只用默认深度;不接图片/新闻垂直接口)
- 博查等备用供应商的实际接入(只保证 F5 的隔离性,不写备用代码)
- M0 已排除项继续排除(登录、多用户、移动端等)

## 验收标准

| # | 对应 | 验证方式 |
|---|------|---------|
| AC1 | F1、F2 | 新任务发"查一下 JLCPCB 是什么公司,给个简介" → agent 无需提示即自动调用搜索(工具卡片可见搜索词与状态),回答基于搜索结果 |
| AC2 | F3、F4 | 问一个需要多来源的问题 → 正文有 `[1]` `[2]` 标注,末尾"来源"小节列出编号+标题+URL,编号一一对应 |
| AC3 | F4 | 纯本地任务("看看 workspace 里有什么文件")→ 回答**不**出现来源小节,也不滥用搜索 |
| AC4 | F1 | 中文时事查询(如"嘉立创最近的新闻")→ 搜索词中文正常,结果可用 |
| AC5 | F5 | 代码检查:Tavily 相关代码只存在于独立工具模块,agent.ts 与前端代码无 Tavily 字样 |
| AC6 | N1 | 临时改错 key → agent 收到搜索失败信息,不卡死,回答说明搜索受阻;验证后还原 |
