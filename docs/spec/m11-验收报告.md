## 二、关键验证证据(摘录)

- **删除类审批**:触发删除 → `GET /sandbox/approvals` 返回 `{kind:'approval', toolName:'mastra_workspace_delete'}` 且文件未被静默删除 → POST approved → 文件真实删除。
- **提权逃生通道**:越界写被沙箱拒 → agent 自动调 `request_sandbox_elevation` → 挂起载荷含命令与被拒原因 → 批准后以 full 档重跑,工作区外文件真实写入;拒绝后 agent 收到原因并改道工作区完成。
- **会话批准**:`mode:'session'` 批准后同线程同类操作免审批直接执行;新线程重新询问(AC12)。
- **档位切换(AC10)**:`requestContext.permission='full'` 时命令越界写直接成功、无审批;缺省档恢复审批询问。
- **连接器**:fetch 授权后经沙箱真实抓取 example.com;memory 授权后经「npx.cmd 全路径 + cmd.exe /c + 用户环境变量 + 网络 + npm 缓存写根」启动成功;未声明能力的连接器不受影响;非法授予返回 400。
- **端到端**:场景 1(搜索→Word,41KB docx 落盘+产物标记)、场景 2/3/4/5/6 均通过;场景 4 中 .env 密钥内容 0 泄露。
- **性能**:沙箱稳态 1.3–2.0s/次,启动预热 3.2–5.4s 吃掉冷启动;连接器长驻子进程无重复启动开销。

## 三、过程中修复的真实缺陷

1. **MCPClient 泄漏**(M10 起潜在):`buildClient` 异常路径不清理实例,静态注册表"重复初始化"防护把后续重建全部卡死(聊天接口 500)。修复:固定 `id` + 异常路径 disconnect。
2. **`listSuspendedRuns` 返回形状**:框架返回 `{runs,total}` 而非数组,路由初版误当数组迭代(会 500),review 时修正。
3. **前端 `permission` 放错位置**:codex 首版放在 body 顶层,后端读的是 `requestContext.permission`,档位会永远不生效。已修正进 requestContext。
4. **`RequestContext` 取值形状**:运行时是类实例且 `permission` 为运行时键,须用 `getRaw()` 而非 `.permission`/`get()`。已按三形态兜底。
5. **`${NPMCACHE}` 被写成空串**(子代理文件写入事故):空路径写根导致 codex 拒收整个 profile、npx 连接器全灭。已修复 4 个 connector.json。
6. **autoResumeSuspendedTools 显式 false**:发现框架在无审批 UI 信号时会默认当 true(bundle `canRenderApprovalButtons ? void 0 : true`),删除该键会重新打开自动恢复,必须显式 false。

## 四、遗留事项(需要你知晓)

1. **浏览器人工确认项**:审批卡片的视觉与点击(四按钮、倒计时)、Word/PPT 产物在预览面板的打开效果 —— 后端行为均已 API 级验证,浏览器层留给你过目。
2. **N9(非 Windows 提示)**:本机无法运行时验证,代码分支已实现。
3. **熔断语义微调点**:熔断计数把每次挂起请求也计入,实际效果是"同一命令键被拒一次后不再询问"(比任务书"两次"更保守,fail-closed 方向)。如需放宽,把 `sandbox-elevation.ts` 挂起路径里的 `recordDenial` 挪到仅 resume 后未批准分支,一行改动。
4. **authorize 接口对空 body** 会报「Unexpected end of JSON input」而非按"授予全部已声明"处理(前端总是传 `{}`,不受影响);后续可顺手加空 body 兼容。
5. **运维纪律**(重要,已写入记忆):codex exec 与 dev server 不并发(双 codex-home 凭据轮换竞态会导致沙箱账户 1909 锁定);codex 子代理禁止触碰 .env、禁止起服务(见 `m11-task.md`「运维发现」)。
6. **建议另立任务**(T11 遗留权衡):把 4 个 npx 类连接器包装进本地依赖,消除"为下载代码而授予网络"的需要(与 setup-python-runtime 同构)。
7. `.env.backup-20260916` 是事故期间的密钥备份,确认无误后可删。
