# M3 定时任务 Checklist

> 每一项通过运行代码或观察行为来验证。括号内为验证方式;[ACx] 对应 spec 验收标准。

## 实现完整性

- [ ] 页面创建定时任务(每天 09:00 汇报当前时间)→ 列表出现、状态运行中、下次运行时间正确([AC1])
- [ ] 创建后关联任务线程已生成(验证:列表入口可跳转 /task/:threadId,[AC1])
- [ ] 对话创建的定时任务出现在列表中(验证:对话说"每天 12 点问我今天学到了什么" → 刷新列表,[AC2])
- [ ] 立即执行 → 关联任务线程出现新的执行内容(验证:进关联任务查看,[AC3])
- [ ] 暂停/恢复状态切换正确(验证:状态"已暂停"↔"运行中",[AC3])
- [ ] 删除调度后列表消失、关联线程历史保留(验证:删除后进 /task/:threadId,[AC4])
- [ ] 自定义 cron 非法值明确报错(验证:填 `abc` 提交,[AC5])
- [ ] 空状态文案正确(验证:无定时任务时目测,[F1])

## 集成

- [ ] cronToText 转换正确(验证:每天→"每天 09:00";每周→"每周一 08:30";工作日;每月;自定义原样)
- [ ] 重启后端后列表仍在、调度继续(验证:重启 + 刷新,[AC6])
- [ ] M0~M2 回归抽查:建任务/搜索/附件/网盘页正常(验证:各抽查一轮,[AC7])

## 编译与质量

- [ ] 后端启动无报错(验证:npm run dev 日志)
- [ ] 前端 tsc 通过(验证:app/ 下 tsc --noEmit)
- [ ] 无密钥泄漏(验证:提交历史无 key)

## 端到端场景

- [ ] 场景 1(主流程):页面创建 → 列表正确 → 立即执行 → 关联任务可见执行内容 → 删除
- [ ] 场景 2(对话创建):对话创建 → 列表可见 → 暂停 → 恢复
- [ ] 场景 3(持久化):重启后端 → 列表与调度继续生效
