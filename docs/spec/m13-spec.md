# M13 产物文件卡与系统操作菜单 Spec

## 背景

对话中 AI 生成的文件目前渲染为统一的「点击预览」短卡：点击进站内预览，此外没有任何文件级操作。用户无法从卡片直接用系统程序打开文件、定位到所在文件夹、另存到别处或复制本机路径，也看不出文件类型差异。

本产品后端（Mastra server）运行在用户本机，产物文件都是本地文件，具备执行系统级文件操作的条件。参考产品（千问桌面端）的做法：长卡片 + 文件类型图标 + 右侧三点菜单，菜单含「打开 / 打开文件夹 / 另存为 / 复制路径 / 打开方式」，其中「打开方式」展开子菜单列出本机可打开该类型的应用（标注默认程序）。

现状要点：产物卡由消息文本中的产物标记解析而来，携带文件名与产物路径标识（非本机绝对路径，出于安全不在消息中暴露）；点击卡片走既有的站内预览链路（docx/xlsx/pptx/pdf 已支持）。

## 目标

- 产物卡升级为长卡样式，文件类型一目了然（专属图标 + 类型与大小标签）
- 三点菜单提供本机文件操作：打开、打开文件夹、另存为、复制路径、打开方式
- 「打开方式」子菜单枚举本机可处理该文件类型的应用并标注默认程序，点击即用该程序打开
- 站内预览能力保持不变

## 功能需求

### 卡片样式

- **F1 长卡布局**：产物卡为通栏长卡：左侧类型图标、中部文件名与「类型 · 大小」副标题（如 `PDF · 110.4 KB`）、右侧三点按钮。同一消息内多个产物各占一张卡，样式一致。
- **F2 类型图标**：按扩展名显示专属图标（矢量绘制、近似各类型软件标识风格）：pdf 红、docx 蓝、xlsx 绿、pptx 橙、图片类紫、文本/代码类中性色、未知类型通用文件图标。图标获取失败不影响卡片其余部分。
- **F3 大小显示**：副标题显示文件大小（人类可读，如 KB/MB）。大小获取失败时只显示类型标签。
- **F4 点击预览保持**：点击卡片主体打开既有的站内预览（行为与现状一致）；点击三点按钮打开菜单，不触发预览。

### 三点菜单

- **F5 菜单内容**：三点菜单纵向排列五个入口：打开、打开文件夹、另存为、复制路径、打开方式（右侧带展开箭头）。
- **F6 打开**：用系统默认程序打开该文件。
- **F7 打开文件夹**：在系统文件管理器中打开文件所在文件夹并选中该文件。
- **F8 另存为**：把产物保存到用户指定的本地位置（浏览器环境下表现为标准下载）。
- **F9 复制路径**：把产物的本机绝对路径复制到系统剪贴板，成功后给出可见的轻量反馈。
- **F10 打开方式子菜单**：悬停/点击「打开方式」展开二级菜单，列出本机可打开该文件类型的应用（应用名 + 应用图标，默认程序标注「默认」），点击某应用即用它打开文件。列表为空（系统未注册任何关联程序）时显示「没有可用的应用」占位。
- **F11 菜单交互**：点击菜单外部或 Esc 关闭；菜单打开时不阻塞页面滚动；连续操作（打开→关闭→再打开）状态正确。

### 卡片内联预览

- **F16 PPT 内联预览**：pptx 产物卡在卡头下方直接内嵌幻灯片预览区，复用既有的 pptx 分页渲染能力，按页纵向滚动展示全部幻灯片。渲染失败（文件损坏等）时预览区显示失败提示，卡片其余功能不受影响。
- **F17 HTML 内联预览**：html 产物卡在卡头下方直接内嵌网页预览区，以沙箱化方式渲染（不授予其访问宿主页面与会话数据的权限），高度固定可内部滚动。渲染失败显示提示。
- **F18 预览区与预览栏的关系**：点击内联预览区在右侧预览栏打开该产物（进入既有的大屏预览与缩放交互）；卡片上的三点菜单行为（F5-F11）不受内联预览影响。docx/xlsx/pdf 等其余类型不内联，保持点击卡片进预览栏的现状。

### 后端支持

- **F12 产物路径解析**：后端提供接口，把前端持有的产物标识解析为本机绝对路径，并返回文件大小。解析结果必须限制在产物允许的目录边界内，越界拒绝。
- **F13 系统操作端点**：后端提供执行 F6/F7/F9 操作的端点（打开、定位文件夹、返回绝对路径供复制），以及 F10 的应用枚举端点（返回应用名、图标、是否默认）与按指定应用打开的端点。
- **F14 应用枚举实现**：枚举基于 Windows 的文件关联信息（默认程序 + 已注册的打开方式列表），应用图标从关联的可执行文件提取，转成前端可显示的图片格式；提取失败的应用降级为通用图标。结果按文件扩展名缓存，避免重复枚举。
- **F15 失败反馈**：任一操作失败（文件已不存在、系统调用失败等）时，前端以轻量提示呈现失败原因，不静默、不崩溃。

## 非功能需求

- **N1 平台范围**：本机操作按 Windows 实现（explorer / shell 默认程序 / 注册表关联）。非 Windows 环境下菜单仍显示，「打开/打开文件夹/打开方式」降级为不可用或走各自平台的等价实现（由 plan 决定），「另存为/复制路径」不受平台限制。
- **N2 安全边界**：所有文件操作以产物标识为输入、以后端解析的绝对路径执行，前端传入的任何路径片段不得直接拼接执行；目录边界校验在每次操作时执行；应用枚举与打开只接受后端枚举结果中的应用标识，不接受任意命令行。
- **N3 文本安全**：文件名、应用名等一切外部文本以 React 文本节点渲染，防注入。
- **N4 中文界面**：菜单与提示文案为中文，与现有风格一致。
- **N5 视觉一致**：长卡与菜单沿用现有配色、圆角、阴影、字号规范；三点菜单为浮层（带阴影圆角面板），风格与现有下拉菜单（如模型选择器）一致。
- **N6 无障碍**：三点按钮有可读名称，菜单可键盘导航（方向键移动、Enter 执行、Esc 关闭）。
- **N7 性能**：应用枚举在首次打开子菜单时进行并缓存；卡片渲染不做同步文件系统调用（大小等信息异步加载，加载中不阻塞卡片显示）。

## 不做的事

- **docx/xlsx/pdf 的内联预览**：内联仅覆盖 pptx 与 html（用户指定的两类），其余类型保持点击进预览栏的现状。
- **附件卡与其它文件入口**：用户上传的附件卡、网盘页、右侧预览栏文件列表不改造，保持现状。
- **卡片的编辑类操作**：重命名、删除、移动、拖拽不在菜单内。
- **「固定到主屏」「分享」等扩展菜单项**：只做图中出现的五个入口。
- **非 Windows 的本机操作一等支持**：见 N1，本期以 Windows 为准。
- **产物历史的独立管理页**：不做跨对话的产物汇总视图。
- **打开方式的自定义/浏览更多应用**：子菜单只列系统注册的关联程序，不提供「在这台电脑上查找其它应用」。

## 验收标准

- **AC1**（F1-F3）：触发生成一个 Word 与一个 PDF 产物，两张卡均为长卡布局，图标分别为蓝/红系，副标题显示正确类型与大小。
- **AC2**（F4）：点击卡片主体进入站内预览；点击三点按钮出现菜单且不触发预览。
- **AC3**（F5、F11）：三点菜单含五个入口；点击外部或 Esc 关闭；反复开关状态正常。
- **AC4**（F6）：点「打开」后文件以系统默认程序打开（如 .docx 由 Word/WPS 打开）。
- **AC5**（F7）：点「打开文件夹」后资源管理器打开该文件所在目录且文件处于选中态。
- **AC6**（F8）：点「另存为」后浏览器进入该文件的标准下载流程，保存成功内容完整。
- **AC7**（F9）：点「复制路径」后在资源管理器地址栏粘贴，得到该产物的本机绝对路径；界面出现成功反馈。
- **AC8**（F10）：对 .pdf 与 .docx 分别打开「打开方式」，子菜单各自列出本机关联应用，默认程序带「默认」标记，应用图标正常显示（无图标的应用降级为通用图标）；点击其中一个非默认应用，文件用它打开。
- **AC9**（F10）：对一个系统未注册任何关联程序的扩展名（可用临时自造扩展名验证），子菜单显示「没有可用的应用」。
- **AC10**（F12、N2）：构造越界产物标识请求路径解析/操作，后端拒绝并返回错误，不执行任何文件操作。
- **AC11**（F15）：删除产物文件后再点「打开」，界面出现失败提示（文案含原因），无崩溃。
- **AC12**（F14、N7）：同一扩展名第二次打开子菜单明显快于第一次（缓存生效）；首次打开期间菜单不卡顿。
- **AC13**（N3）：文件名含 HTML 特殊字符（如 `<b>x</b>.html`）时，卡片与菜单按纯文本显示，不发生注入。
- **AC14**（N6）：键盘可完成：聚焦三点按钮 → Enter 开菜单 → 方向键在菜单项间移动 → Enter 执行 → Esc 关闭。
- **AC15**（F16）：生成一个 pptx 产物，卡片内直接可见幻灯片画面并可滚动翻页，无需点击进预览栏。
- **AC16**（F17）：生成一个 html 产物，卡片内直接渲染出网页画面，内部可滚动；宿主页面的会话数据不受该页面影响。
- **AC17**（F18）：点击 pptx/html 卡片的内联预览区，右侧预览栏打开该产物；卡片三点菜单五项功能照常可用。
- **AC18**（F16/F17 降级）：构造一个损坏的 pptx 产物卡，预览区显示失败提示，卡片其余部分与菜单正常。
