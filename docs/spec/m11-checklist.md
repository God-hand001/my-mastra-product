# M11 沙箱体系 Checklist

> 对应 `m11-spec.md` 的 AC1–AC17 + `m11-plan.md` 的架构验证点。
> 每一项通过**运行代码或观察行为**来验证,不靠读代码判断。

## 验收纪律(两条,Phase 0 交过学费)

1. **正反配对**:每条「应被拒」必须配一条**同形式**的「应成功」。两者都失败说明命令根本没执行,拒绝断言无效。
2. **辨别真假拒绝**:真拒绝的 stderr 含 `PermissionError: [Errno 13]`(Python)或 `Access is denied.`(cmd)。
   若见「文件名、目录名或卷标语法不正确」——那是**语法错误伪装的假阳性**,不算通过。

## 一、子进程围栏生效(Phase 2)

- [x] **表格建表:界内成功**(AC1)。让 agent 生成一份含公式的表格 → 产物落盘、公式重算无错误报告
- [x] **表格建表:越界被拒**(AC1)。让 agent 写一段用直接文件写入操作、目标在工作区外的建表脚本 → 返回失败且原因可读,该文件确实未生成
- [x] **内容黑名单已移除**(AC2)。提交一段**合法但正文含 `subprocess` 字样**的建表脚本(如注释里提到它)→ 正常执行成功。改造前会因字符串匹配被拒
- [x] **命令执行:界内成功**(AC3)。让 agent 在工作区内创建目录并写文件,分别测:中文目录名、含空格路径、含重定向与逻辑与的命令串 → 三者均成功且文件内容正确
- [x] **命令执行:越界被拒**(AC3)。同形式让 agent 在工作区外创建目录 → 被拒,该目录未出现
- [x] **后台进程同样受限**(AC4)。以后台方式执行一条越界写命令 → 同样被拒(证明前台与后台共用同一围栏,非只覆盖一条路径)
- [x] **Word 端到端**(AC5)。真实对话让 agent 生成一份多章节 Word 文档 → .docx 产出、可在预览面板打开、目录与页脚正常
- [x] **PPT 端到端**(AC5)。真实对话让 agent 生成一份多页 PPT → .pptx 产出、可在预览面板打开、版式正确
- [x] **临时文件不落用户临时目录**(AC5)。上两项执行后检查系统临时目录 → 无本产品的转换任务残留目录
- [x] **连接器可用且往返不中断**(AC6)。启用一个本地连接器 → agent 能真实调用其工具;在同一会话内连续调用三次以上 → 均成功(验证长驻双向通道未被围栏切断)
- [x] **连接器网络按声明生效**(AC6)。声明为联网的连接器能抓取公开网页;未声明的连接器其网络访问受限
- [x] **连接器失败不扩散**(AC6)。把某连接器的命令改为不存在的可执行文件 → 扩展面板显示该连接器失败原因,对话不中断,其他连接器仍可用
- [x] **三档策略边界符合定义**(AC7)。分别以只读、工作区可写、项目目录可写三档执行同一组读/写/联网探测 → 各档的允许与拒绝范围与定义一致

## 二、拒绝判定与逃生通道(Phase 3)

- [x] **拒绝带标记与可读原因**(AC8)。触发一次越界写 → 工具返回结果标记为疑似沙箱拒绝,原因文本包含被拒的路径
- [x] **命令自身失败不被误标**(AC8)。执行一条不存在的命令 → 结果**不**标记为沙箱拒绝(避免把普通错误当权限问题)
- [x] **不陷入重试死循环**(AC9)。让 agent 反复尝试同一个必然被拒的操作 → 达到上限后转为如实告知用户,对话正常结束,不无限循环
- [x] **完全访问档自动放行**(AC10)。切到完全访问档,重做一次原先被拒的越界写 → 无需审批直接执行成功
- [x] **默认档恢复审批**(AC10)。切回默认档,同一操作 → 重新出现审批询问
- [x] **审批请求内容完整**(AC11)。触发审批 → 用户可见:将执行的命令、工作目录、被拒原因、请求放宽的范围
- [x] **拒绝但继续**(AC11)。审批时选「拒绝但会话继续」→ agent 收到拒绝、改换方案继续对话,不中止
- [x] **超时按拒绝处理**(AC11)。触发审批后不响应,等到超时 → 按拒绝处理,工具返回而非永久挂起
  - ⚠️ 2026-09-17 用户定向**取消倒计时**:待决审批一直等待决定,不自动拒绝(请求正常结束不悬挂,满足 D8「无工具永久挂起」的原始意图;弹窗常驻显示,用户随时可决定)
- [x] **批准后重跑成功**(AC12)。审批时选「本次允许」→ 同一操作以更宽策略重新执行成功,结果回流对话且 agent 视其为该次工具调用的结果
- [x] **本会话允许生效一次即止**(AC12)。选「本会话内同类允许」后,同类操作不再询问;新开会话则重新询问
- [x] **删除类操作真正征求同意**(R2 修复验证)。让 agent 删除工作区内一个文件 → 出现审批询问而非静默执行。改造前该审批被自动批准吞掉
- [x] **无工具永久挂起**(D8)。完成上述审批场景后观察 → 没有请求卡住不返回

## 三、启动、失败与安全

- [x] **启动自检可读**(AC13)。启动服务 → 日志显示沙箱档位、凭据目录、拒读路径条数
- [x] **二进制缺失时明确报错**(AC13)。临时重命名沙箱二进制后启动 → 日志给出明确错误与可直接复制的修复命令;服务仍能启动(不黑屏)。恢复名称后正常
- [x] **未初始化时拒绝执行**(AC16)。指向一个未完成初始化的凭据目录 → 工具调用返回明确错误,**不**退回无防护执行
- [x] **环境变量不含机密**(AC17)。检视一次真实沙箱调用传入的环境变量集合 → 不含模型 API 密钥等机密项
- [ ] **非 Windows 平台明确提示**(N9)。在非 Windows 环境下解析沙箱运行时 → 给出不支持的明确提示,而非静默失败或裸跑
  - ⚠️ 本机为 Windows,无法运行时验证;代码有 `process.platform` 分支(sandbox-approval.ts 的 externalWrite 非 win32 分支、connector-runtime 同),留待有非 Windows 环境时补验

## 四、性能

- [x] **稳态开销达标**(AC15)。固定策略连续执行同一轻量命令 4 次 → 后续三次的均值 ≤2s
- [x] **预热吃掉冷启动**(AC15)。服务启动完成后,用户的第一次工具调用耗时接近稳态,而非首次冷启动的量级
- [x] **长驻子进程只付一次**(N1)。连接器启动后连续多次调用其工具 → 单次调用耗时不含沙箱启动开销

## 条件项说明

以下两项的具体验证方式取决于执行期的决策门结论,门未出结论前按「待定」处理,不得跳过:

- **连接器启动策略**(D6):若定量结论为并发预热,验证「启动阶段完成全部连接器预热且总耗时可接受」;若为懒启动,验证「首次调用时启动、失败原因在此时写入面板」
- **审批链路实现**(⑥):若设计 A 成立(工具中途挂起),验证「挂起期间前端可取到审批载荷、决定后恢复同一次调用」;若落设计 B,验证「拒绝结果携带建议,提权工具经原生审批闸门执行」
